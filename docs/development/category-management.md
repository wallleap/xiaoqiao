# 收支分类管理

收支分类是账目明细维度，与预算分类、标签相互独立。设置页提供“管理收支分类”入口。

## 能力

- 支出与收入分类分开展示。
- 新增根分类或任意层级子分类；允许直接使用父分类记账，不强制细分。
- 编辑名称、图标和父分类，移动后追加到目标父级的同级末尾。
- 首屏只显示一级分类，点击名称区域进入子分类列表，逐层浏览；标题返回、路径返回和系统返回优先回到上一级。
- 使用中分类支持同级拖拽排序，不再显示上移、下移；已归档视图不参与排序，保留通往归档子分类的父级入口。
- 归档与恢复。归档父分类前必须先归档其启用中的子分类。
- 至少保留一个启用中的收入分类和一个启用中的支出分类。
- 已归档分类继续用于历史账目展示；编辑旧账目时仍可保留原分类。

数据库沿用 `categories.parent_id` 单一树结构，`category_closure` 递归视图用于统计和循环检查。名称在相同账本、类型、父分类下唯一，分类书籍归属和收支类型不可修改。

自定义图片图标仍需后续接入系统文件选择器；本轮使用现有内置彩色分类图标。

## 验证

`Categories` 原生测试覆盖三级分类、同级重名拒绝、循环移动拒绝、改名换图标、同级排序、父分类归档保护、逐级归档与恢复。`CategoryUI` 覆盖设置页入口、分类树和新增分类 Sheet。完整回归继续覆盖原记账与预算路径。

最终验证：分类业务测试 1/1、分类 UI 1/1、完整 API 26 原生回归 50/50 通过；真机截图确认父分类和子分类的层级缩进、同级排序及管理操作布局。

## 内置图标资源命名与新增

资源文件统一为 `colorful_iconNNNNN.svg`，当前 371 个文件已增加 `colorful_` 前缀，SVG 内容不变。数据库 `categories.icon_key` 继续保存稳定的 `iconNNNNN`，已有语义键与旧 `colorful_icon_*` 别名继续通过映射解析，不批量修改用户数据库。

新增流程：

1. 将新 SVG 放入 `entry/src/main/resources/base/media/`，例如 `colorful_icon00372.svg`。使用未占用的新编号，不重排或复用旧编号。
2. 在项目根目录执行 `python3 tools/generate-category-icon-catalog.py`，重新生成 `ColorfulCategoryIcons.ets`。不要手动修改生成文件；平常新增不需要 `--legacy-ref`，也不修改旧别名映射。
3. 重新编译安装后，分类编辑 Sheet 的图标网格会读取生成目录并显示新图标。
4. 用户选中并保存分类时，分类创建/更新流程把 `icon00372` 写入 `categories.icon_key`；内置图标目录无需逐个插入数据库。

仅增加可选图标不需要数据库升级。若要自动创建新分类、修改已有分类的默认图标或替换某编号图形，则是另一项数据/产品变更，应单独确认范围。内置资源随应用发布，历史图标必须保留以兼容旧账本与备份；用户自定义上传图标沿用现有附件/资源备份机制。

转账业务图标统一使用 `colorful_icon00372.svg`（列表、记一笔、详情和统计），保持原色；交换转出/转入账户的操作按钮仍使用原有交换箭头。收入“其他”语义键按收入类型解析到 `icon00373`，支出“其他”映射不变。导入自动创建收入分类时写入 `icon00373`，支出继续写入 `other`；复用已有分类时不覆盖其已选图标，未批量修改历史分类数据。


## 彩色分类图标背景

所有彩色分类图标统一使用 CategoryIconBadge，覆盖首页（含预付款入口）、记一笔分类网格/紧凑栏/金额区、分类管理列表和图标选择器、账单明细、搜索、账目详情、统计分类排行及明细。账户品牌图标、标签及预算分类色块不属于分类图标，本次不改。

背景采用真实超椭圆方程 |x/a|^4 + |y/a|^4 = 1（96 点封闭 Path），不再使用圆形灰底，也不裁切 SVG 图案。常规列表为 44vp 背景配 28–30vp 图标，首页保留 48vp 背景配 28vp 图标；选择器保持原有网格占位，用 36vp 背景配 26vp 图标；紧凑分类栏同为 36/26vp，记一笔常规网格为 44/30vp，详情和金额区为 48/32vp。现有选中边框、勾选标识和子分类入口保持。

生成器 tools/generate-category-icon-catalog.py 根据 SVG path 的 fill、坐标数量、同色系合并评分和饱和度估算图标主色，排除白色高光及中性阴影；这是自动估算，不是逐像素面积分析。对应背景资源位于 base/dark/element/category_icon_backgrounds.json：浅色 alpha=0x0F（约 6%），深色 alpha=0x1F（约 12%），两模式使用同一主色。按 Resource.id 匹配目录中的背景资源，因此旧语义 key 和 legacy alias 映射到相同图片后，也会自动匹配相同背景；不变更数据库图标键。

新增图标后仍运行 `python3 tools/generate-category-icon-catalog.py`，该命令同时更新静态图标目录、373 个背景资源（数量随图标增减）及深浅模式配色，不手改生成文件。无有效彩色 fill 时使用中性蓝灰回退。当前 373 个图标均提取到彩色主色。

本轮验证：运行目录生成命令，核对 373 个资源、深浅色一一对应、别名解析及引用完整性；git diff --check。未运行构建、自动化测试或设备验证。实际需查看系统深浅色切换、选择器密度、紧凑栏与常规分类网格及转账/收入其他/预付款图标；多色图标的自动主色可能需要后续人工微调。

CategoryIconBadge 成员命名避开 ArkUI 通用方法：尺寸参数使用 badgeSize，背景解析方法使用 badgeBackgroundColor，避免与 CustomComponent.size/background 冲突；所有调用同步更新。依据设备构建错误修正，未改变尺寸、配色或超椭圆规则。

超椭圆定位修正：Path.commands 的坐标单位为 px，而 Path/Stack 的 width/height 数值单位为 vp；生成轮廓前使用 UIContext.vp2px(badgeSize) 转换，避免高密度屏幕上背景缩在左上角。前景图标及外层尺寸继续使用 vp，无需针对不同分辨率硬编码缩放。已核对本地 SDK path.d.ts 单位声明；未构建或设备验证。

主色提取修正：icon00373 虽显示为绿色，SVG 中仍含被覆盖的红色底层路径。评分改用坐标数量（不受导出小数位数影响），色相相差 30° 内的同色系合并投票，再选择该色系的代表色，避免多个绿色分色被单条红色路径压过。icon00373 背景主色现为 #1DCE75，浅色 #0F1DCE75、深色 #1F1DCE75。该算法仍是配色启发式，不代表严格的渲染可见面积分析；多色和覆盖复杂的图标仍可能需要人工微调。
