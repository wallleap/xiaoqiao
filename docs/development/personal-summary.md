# 我的页汇总与加载状态

## 统一笔数口径

个人汇总与账本列表复用 `LedgerUsageQuery.ets` 的只读行集：

- 有效支出、收入、转账，每笔计一次。
- 已入账的预付款付款、预付款退款，每条计一次。
- 核销已生成支出时，由对应支出计入，不再重复统计核销事件。
- 普通退款／报销到账不额外计数；草稿、已删除记录、未提交导入不计。
- 包含已归档账本，排除已删除账本。

`usageSummary()` 对共享行集计算最早日期和总笔数；`books()` 按 book_id 聚合，同一数据库快照下各账本笔数之和等于个人总笔数。预付款事件通过 project_id 关联项目取得 book_id。计数使用十进制字符串，不改表结构或持久化冗余计数。

记账天数仍为最早有效记录日期至今天，包含首日，成功读取空账本时最少为 1；净资产仍沿用资产页口径，不改变资产、负债、预付款或汇率计算规则。

## 三项显示状态

| 状态 | 数值区 | 辅助信息 |
| --- | --- | --- |
| 首次尚未成功读取 | 计算中… | 不显示默认 1／0 冒充结果 |
| 已有成功值，正在刷新 | 保留上次成功值 | 更新中 |
| 成功 | 最新数值，含合法的 0 | 清除加载和错误信息 |
| 首次失败 | 读取失败 | 明确错误原因、重试按钮 |
| 已有成功值后刷新失败 | 保留上次成功值 | 更新失败、错误原因、重试按钮 |

`PersonalSummaryState.ets` 统一数值和辅助状态文案；LocalBackupPage 只展示父页面传入状态，不自行触发数据库请求。净资产使用最后一次成功值缓存，汇率缺失不会用空字符串覆盖；明确列出缺失币种，账户读取失败则给出余额读取失败提示。缓存仅在当前运行内保留，首次启动必须读取后才能展示有效数值。

页面普通载入仍刷新三项；切换到「我的」同时刷新记账汇总和净资产。异步完成时通过 @State／@Prop 自动更新。点击重试刷新对应结果；如果整个账本尚未读成功，则重走账本载入。保留原有防重复刷新，不新增轮询或跨零点定时器。

## 验证

- `node tools/verify-personal-summary.mjs`：执行生产状态函数及异步刷新方法，覆盖首次、刷新保留旧值、读取失败、缺失汇率、恢复成功、合法零值。
- `python3 docs/database/verify_book_covers.py`：共 12 项（含 V9 基础），直接执行生产账本计数 SQL，校验预付款付款／退款、草稿、归档、删除、最早日期与汇总之和。
- `node tools/verify-book-covers.mjs`：账本列表新增共享 SQL 后继续验证读取、封面和版本冲突。

本轮未执行原生构建、真机加载状态／网络失败验证；没有修改或迁移设备数据。

## 快捷入口

我的页移除资产账户、图表统计两个重复入口，保留底部资产／统计 Tab。账本管理、分类设置、预算分类、修改预算、账单明细、自定义标签及汇率查询按三列排列，共 7 个入口。mine_icon_assets 和 mine_icon_charts 图标文件保留；不改资产、统计页面及导航回调。

汇率入口使用 mine_icon_exchange_rates.png 并打开独立 HDS 子页面，支持选择基准币种、搜索、公开参考汇率及缓存／错误状态，详见 [汇率查询](exchange-rates.md)。

### 快捷入口自适应

“我的”快捷入口按卡片实测宽度减去左右各 12 vp 内边距计算列数，每格最小目标宽度 72 vp，最多 7 列，不固定三列。常规字体下，296 vp 内容区显示四列，272 vp 显示三列；大字体按 UIContext 当前 fp/vp 比例扩大目标宽度并增加行高。宽屏、横屏和分屏时重新排列，入口顺序与点击行为不变。布局计算与汇率页共用 `presentation/layout/AdaptiveGrid.ets`，本地验证使用 `node tools/verify-adaptive-grids.mjs`。
