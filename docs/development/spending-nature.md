# 支出性质

“支出性质”是独立于收支分类和标签的第三个支出维度：

- 收支分类继续负责带图标的层级分类与预算统计。
- 支出性质为单值，描述消费目的；目前包含生存保障、体验享受、成长提升、突发支出。
- 标签保持多选，用于出差、可报销、家庭等交叉检索。
- 收入和转账不显示支出性质。

## 数据结构

V3 迁移新增全局 `spending_natures` 表，并在 `transactions.spending_nature_id` 保存单值引用。性质允许用户新增、改名、换色、归档和恢复；内置标识用于界面说明，不限制编辑。

四条内置性质使用稳定 ID，`color_token` 只保存语义颜色名，亮色和深色资源分别映射。自定义性质名称去除首尾空白后为 1 至 20 个字符，并拒绝与未删除性质重名。归档至少保留一个可用性质；历史账目继续保留已归档性质，编辑旧账目时仍可显示。

迁移只新增表、索引、触发器和可空列，不回填、不猜测历史账目的性质。升级前通过系统 `RdbStore.backup` 创建 `_before_spending_nature_v3.db`。迁移在事务中核对账本、分类、交易、资金变动、预算和标签数量及交易金额摘要，并执行外键与完整性检查；失败时回滚。

## 兼容

`schema_migrations` 增加版本 3。旧 V2 数据库在打开时先备份再升级到 V3。旧 V2 `.xqbackup` 的清单仍可进入预览：候选数据库副本会先执行同一 V3 迁移，再与当前结构、数据计数和资源引用核对。新导出清单使用 `schema=3`。

## 界面与验证

记账页的支出表单使用浅色/深色自适应的彩色胶囊单选；再次点击不取消，使用“清除”恢复未设置。设置页“分类与标签”卡片进入支出性质管理。

原生隔离测试覆盖 V2→V3 数据不变、V3 迁移中途失败回滚、四条内置性质、自定义新增/改名、重名拒绝、归档/恢复、无效引用拒绝，以及新增和编辑账目时性质往返。UI 测试覆盖设置页性质入口、记账页选择性质及截图。备份回归验证旧 V2 完整包会在候选副本上升级后恢复，原交易内容与资源恢复流程不变。

最终验证：主应用和测试包 Hvigor `assembleHap` 通过；API 26 模拟器完整原生回归 45/45 通过；主机业务检查 44/44、schema 设计测试 57/57、基础 schema 82 条语句一致性检查通过。真实用户数据库已从 V2 升级到 V3，升级前文件 `xiaoqiao_before_spending_nature_v3.db` 已生成，首页账目与预算正常读取。
