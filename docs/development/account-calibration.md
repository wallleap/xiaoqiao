# 账户余额校准与调整记录

2026-11-05，基于`7e8708a`。用户确认实现人民币账户实际余额/待还金额校准、确认预览和调整历史；复用已有表，不迁移，不改期初和历史交易，校准不计收支或预算。验证只操作UUID隔离库。

## 页面与金额语义

账户编辑的余额卡新增“校准余额”和“调整记录”。如果账户名称、品牌或净资产规则有未保存修改，先保存账户信息再校准，避免校准成功退出时丢失其它输入；查看调整记录后返回仍保留编辑草稿。

校准页采用HdsNavigation、原生金额输入、系统字体及DIN数字，沿用现有浅灰背景、白卡和主题颜色。资产账户选择“可用余额/透支金额”，负债账户选择“待还金额/溢缴余额”；金额输入非负，待还/透支转为负账面余额，可用/溢缴转为正余额。可校准到0，但余额相同不生成无意义记录。原因可选，最多200字符，留空保存“手动校准余额”。

进入校准页时重新读取实时账户余额与版本，不使用账户列表的缓存快照；读取完成前不能提交。页面同时显示当前账面余额、目标余额和精确差额。点击预览并校准后，再显示一次账户、前后余额、差额和不计收支/预算的确认弹窗；取消不写库。校准完成后返回账户列表并刷新余额/净资产。归档账户可查看历史，新增校准须先恢复使用；删除或不可用账户在写入时拒绝。

余额调整记录按发生时间和ID倒序，每页20条，可加载更多；包括期初和校准，显示调整前、调整后、差额、时间和原因。金额用中性样式，不把正差额当成收入。只读posted记录，草稿不可见。数据库保存毫秒时间，UI按设备本地时间显示到分钟。分页期间新插入的较新记录在重新进入页面后读取，旧记录不可修改，因此游标不会因旧记录改动失效。

## 写入与并发

`AccountCalibrationCommand`携带稳定操作ID、账户ID、预览时的账户revision、预览余额、目标余额及原因。Money/BigInt计算差额，前余额、后余额和差额分别检查最小单位安全整数边界。仅CNY，最多两位小数；不使用浮点计算。

RdbAccountRepository.calibrate在原有RdbSession串行事务中：

1. 重新校验账户未删除、未归档、CNY、revision匹配。
2. 从v_effective_movements逐笔读整数文本，用BigInt计算当前余额，必须等于预览时的before。
3. 通过revision谓词递增账户版本，防止并发账户编辑/归档/校准覆盖。
4. 追加draft `balance_adjustments(kind=calibration)`，记录before/after/delta/reason；追加同账户、同时间、同差额的adjustment movement。
5. 发布为posted；已有SQL触发器再次核对真实当前余额和movement，提交后才进入有效余额。

任一步失败回滚账户revision、调整记录与movement，不留下半条或草稿。重复操作ID拒绝，不重复记差额。两个预览同时提交时，第一笔成功后另一笔因版本或余额过期拒绝。普通收支/转账不改变账户元数据revision，因此还必须比较当前余额，不能只比较revision。

余额冲突后固定底部操作改为“刷新余额”，保留用户填写的目标和原因；刷新更新当前余额/版本、重新计算差额，再恢复“预览并校准”。刷新动作始终位于滚动内容之外，用户必须重新确认，不能自动重试。写入结果不确定时提示先刷新余额并检查记录，保留操作ID防止重复追加。

校准作用于全局共用资金账户，不归属某一个账本；读取余额包含所有账本的有效资金变动。校准事件是一次固定差额，不是永久锁定余额。后续记账或编辑、删除以前的交易仍可能改变当前余额；旧校准记录保存当时的前后数值，不追溯改写，也不自动生成第二次校准。校准不新建transactions，因此不进入首页普通账目、收入、支出或预算，账户是否计入总资产仍按原设置。调整记录不提供直接编辑/删除；发现录入错误可再次校准，保留完整过程。本轮没有新增撤销接口。

### 验证中发现并修正的问题

- 首轮设备23/24通过，三个新增持久层用例均通过；UI预览继承了资产列表中上一笔转账删除前的缓存余额。写入层正确拒绝过期before，未产生校准记录。改为每次进入校准页重新读取实时账户快照，读取完成前禁止提交；测试增加真实文字断言，不能只等待一个可能返回null的节点。
- 随后两轮持久层仍通过，UI在余额冲突刷新处失败。增加失败节点文本和现场截屏后，确认刷新按钮在滚动内容底部被固定操作区裁切，点击未生效。改为冲突时固定底部按钮显示“刷新余额”，刷新重算后恢复“预览并校准”；新增刷新操作可见范围断言。保留全部余额、历史和统计断言，未改写数据规则以绕过失败。
- 校准成功后的原HDS提示有三秒生命周期，UI在再次进入固定底部操作前等待其退出，沿用现有账户流程的稳定性处理；仍验证保存后的实际余额和记录。

另发现已有资产列表在删除账目后没有同步刷新账户快照。它属于原删除后的列表刷新逻辑，本轮未扩大范围修改Index；校准页已通过实时读取隔离这一缓存问题，保存校准后沿用原账户保存回调刷新列表。列表缓存刷新可另行修复。
