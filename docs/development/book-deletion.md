# 归档账本的物理删除与余额结转

2026-11-21。用户明确选择物理清除底层账本数据，允许保留不含原交易明细的通用“账本删除余额结转”记录；未结清预付款必须先核销或退款。本轮只编写和主机验证，未操作设备数据库。用户后续要求取消删除前备份，当前删除流程直接执行。

## 用户流程

账本管理仅在已归档条目上显示“删除”，长按菜单同样提供“彻底删除”。未归档、正在操作、预览样例或仍在编辑时不可删除。确认框显示账本名、交易笔数、关联数据删除范围、余额保持规则和备份说明。

确认框明确显示“不创建备份，删除后无法撤销”；取消确认不删除，确认后直接进入删除事务，不再导出完整备份或调用文件保存器。删除成功后刷新账本列表、账目、账户估值和个人汇总。删除后不能再“恢复使用”；如用户此前另有完整备份，可通过现有备份恢复入口恢复整个数据集。

## 数据与余额

删除目标包括账本、全部交易（含草稿和软删除历史）、转账详情、原账户交易流水、FX 快照、退款／报销、预付款项目／事件／分配、预算及额度、分类、标签及关联、导入批次／原始行、附件关联和仅该账本引用的附件元数据。只删除已不被其它交易引用的候选商户。全局账户、币种、汇率缓存、支出性质、可复用导入模板和其它账本保持。

按 `v_effective_movements` 计算各账户当前余额及被删账本的实际余额贡献，用 BigInt 累加。覆盖外币、负债、退款／报销、转账两端、预付款现金流水；preserve 导入及不计资产的记录不产生贡献。所有账户均参加前后校验，包括归档账户。贡献非零时，生成每个账户一笔 calibration 及调整流水，原币种、金额和记录名称均独立于原交易明细：

- before = 当前余额 − 被删账本贡献；
- after = 当前余额；
- delta = 被删账本贡献；
- reason = `账本删除余额结转`。

原交易记录及其流水随后不存在于数据库；通用结转在账户余额校准历史中可见。超过原有安全整数范围时整笔删除中止，不截断或舍入。

## 事务和完整性

V12 新增单例删除上下文、逐账户余额证明、候选资源／商户临时工作表和持久文件清理队列。上下文必须对应已归档、revision 一致、不是当前账本且所有预付款剩余原币／账本金额均为零的账本。原金融删除保护触发器仅在上下文精确匹配该行所属账本时放行，普通单笔硬删除及其它账本的行继续禁止。原 UPDATE、发布和调整不可变保护保留。

`DELETE books` 的 BEFORE 触发器先核验所有账户当前余额，再按依赖顺序清理数据、写入结转并按既有 adjustment_publish 规则发布；AFTER 触发器重新逐账户比较余额，并在同一写连接内检查 foreign_key_check 和 quick_check，最后清空工作表。任一步失败回滚全部数据库修改。未使用 reader 上的未提交查询代替 writer 验证。

取消备份后不再进行跨备份阶段的全量内容指纹扫描。事务内仍按账本 revision、归档状态、当前账本和未结清预付款检查权限，逐账户校验余额。V12 的 backup_uri 上下文字段为兼容已有结构保留，写入 disabled-by-user 策略标记，不代表存在备份文件；不改 V12 结构或校验和。

## 图片与共享资源

只有目标附件和分类资源中、删除后已无附件元数据／其它分类／账户图标引用的路径才进入清理队列。数据库提交后按资源管理器的路径规则清理私有文件，共用资源保留；本流程不额外保留旧文件备份。文件清理失败不把已提交的数据库删除误报为回滚，返回 cleanupPending 提示，并在下次工作区启动时重试。清理任务再次检查引用，避免删除后来重新使用的资源。

未提供取证级介质擦除；这里的物理删除是 SQL DELETE 相关记录及清理独占私有文件，用户此前自行保存的备份可能仍包含原数据。

## 迁移与备份兼容

V12 SQL 不修改既有账户／交易金额。迁移前按项目机制备份数据库，事务内应用，比较数据指纹、外键和 quick_check，失败回滚。新库逐级创建到 V12；普通加载旧库仍要求用户执行既有“备份并升级”入口。

完整包 schema 更新为 12，兼容 schema 2～11；旧备份只在隔离候选库升级。打开 V12 数据库要求临时删除上下文／证明／候选表为空，持久文件清理队列允许非空并在打开后重试。
