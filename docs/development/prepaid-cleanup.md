# 空预付款项目清理（V14）

## 用户可见规则

- 撤销最近一条流水前始终确认。若这是最后一条有效流水，标题为“撤销并删除项目？”，提示同时删除项目及已撤销记录、不可恢复，确认按钮为“撤销并删除项目”。取消完全不写数据。
- 普通撤销仅撤销该流水，项目继续保留。最后一条撤销和空项目清理在同一事务内完成，任何一步失败都回滚。
- 遗留空项目在详情页提供“删除空项目”，另行确认。余额为 0 并不代表可删除：有有效流水（如已全部退款）或未完成草稿仍禁止删除；所有相关流水都已撤销，或从未有流水，才允许删除。
- 清理后从普通预付款入口进入的页面回到项目列表；从分类引用进入的页面回到分类管理，刷新引用和分类，保留浏览层级和滚动位置。

## 数据边界及约束

V14 增加专用清理上下文和写端触发器，按项目 ID、所属账本和预期 revision 精确匹配。V13 的历史保护仍然有效，仅在通过校验的清理事务内部允许物理删除本项目及其撤销记录。项目仍存在有效流水、未完成草稿、跨项目分配、关联交易仍有效或有退款／报销关联时拒绝清理。

清理范围：项目、其已撤销事件、分配、图片关联，以及这些事件独占关联的已撤销账目、账户流水、标签关联、汇率快照。不删除账户、分类、标签实体和其它项目数据。删除前后在同一写端核对所有账户余额；此处“余额不变”指清理本身不产生余额变动，正常撤销仍撤回原付款的账户影响。

专用图片移除数据库元数据并进入现有持久文件清理队列；共用图片保留。文件清理失败下次打开重试，不让数据库删除部分提交。清理完成后上下文和证明表必须为空，外键继续生效。

不会在读取、进入页面或删除分类时自动批量清理旧项目。不为每次删除制作完整备份。V13→V14 首次结构升级沿用本地升级前备份和事务回滚；新库直接创建 V14，旧备份 2～13 升级候选副本后校验，完整备份记录版本 14。

## 文件与验证

- `PrepaidPage.ets`：两种撤销确认、旧空项目确认删除、完成后的返回。
- `RdbPrepaidRepository.ets`／`LedgerWorkspace.ets`：确认标识、版本校验、原子撤销和删除、文件清理队列。
- `PrepaidCleanupMigration.ets`／`PrepaidCleanupSchema.ets`、`schema-v14-prepaid-cleanup.sql`：结构升级和写端校验。SQL 与 ETS 由 `tools/generate-prepaid-cleanup-schema.py` 统一生成，不手动修改产物。
- 数据库打开、版本链、完整备份恢复适配 V14；分类页从详情返回后刷新。

执行 `python3 docs/database/verify_prepaid_cleanup.py` 和 `node tools/verify-prepaid-cleanup.mjs`。覆盖空项目清理、有效／草稿阻挡、版本变化、错误账本、零余额但有历史、直接删除保护、图片独占／共用、事务失败回滚、普通／最后一笔撤销、取消确认，以及真实生产仓储在独立 SQLite 读写连接下的行为。既有分类删除、账本设置／删除、预付款入口主机回归也应通过。

仅使用临时／内存数据库；没有操作设备数据库。原生编译、真机弹窗视觉、原生备份 API 和恢复压缩包尚未验收。
