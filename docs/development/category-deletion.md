# 分类物理删除与历史快照

2026-11-21，用户已确认。分类页不再提供归档／恢复或归档列表，顶部使用“支出／收入”切换，分类行直接提供“删除”。本轮只编写和主机验证，没有操作设备数据库。

## 行为

删除需二次确认，说明不可恢复用于新账目，但历史账单保留原分类信息。有关联子分类（含遗留已停用子节点）、预算分类额度、预付款事件的预设分类或核销账单引用时阻止删除；同类至少保留一个可用分类。不连带删除账单、预算、预付款或子分类。

执行时按当前账本、分类 ID 和 revision 限定目标；失败回滚。普通删除不额外导出完整备份。迁移前仍按原升级流程保存数据库副本。

## V13 的存储边界

- `categories` 仍只承载可管理的分类实体；删除后该行真正不存在，不以 archived_at_ms／deleted_at_ms 隐藏实体。
- `category_references` 是不含名称、图标、排序和归档状态的稳定外键标识，账单继续保留原 category_id。迁移把 transactions 的分类复合外键改指该表，其余列、检查、索引及财务保护保留。
- 存在历史交易（含草稿和软删除历史）引用时，`category_history` 保存名称、图标、完整路径、根分类标识／名称／图标和删除时间；`category_history_nodes` 保存完整祖先链。它们是账单共享的历史快照，不能再用于新记账或分类管理。
- 未被交易使用的分类直接物理删除，不额外生成历史快照，稳定标识也一并清理。已有快照不允许普通修改或删除，历史图标资源继续保留。
- `v_historical_categories` 合并现有分类与快照，供历史列表、退款／报销列表、搜索和详情读取；管理、记账选项、新导入继续只读 categories。
- `category_closure` 补入历史祖先链，保证父分类预算对历史子分类支出的汇总不断开。统计的历史分类使用冻结的根分类信息，名称、图标及层级不丢失。
- 编辑旧账单时，允许保留它目前使用的历史分类，或改成现有可用分类；改走其它分类后不能再把已删除分类用于新关联。新账目不能使用历史分类。入口同时受仓储校验和数据库插入／更新／发布触发器保护。

这里的“物理删除”指删除分类实体，不抹去用户明确要求保留的历史分类快照。不会改旧账单金额、汇率、记账日期、账户流水或余额。

## 迁移、校验与回滚

V13 在单一事务中重建 transactions 的外键定义。先保存原表全字段副本和逐账户余额证明，暂缓外键检查，再在没有旧业务触发器参与复制的阶段逐列原样复制；重建原索引、视图和触发器。写连接上的验证触发器比较新旧交易全字段、逐账户余额，检查 foreign_key_check 和 quick_check，成功后清空证明表并结束外键暂缓。

暂缓外键期间的重建会产生中间引用缺口；在恢复即时外键检查前必须先通过写连接完整性校验，不能把读连接的旧数据当作校验依据。任一语句或证明失败，事务回滚恢复原表、视图、索引和触发器。打开 V13 时检查版本链、校验和及删除临时证明表为空。

实际分类删除也在写连接内执行：先检查业务引用和最后一个分类规则，再记录交易 ID／原币金额／账本金额／revision 及各账户余额证明，生成所需历史快照并删除实体；删除后比较两侧证明、外键和 quick_check。异常整体回滚。归档账本物理删除通过自己的既有余额证明流程执行，不对每个内部分类重复扫描，并同时清理该账本快照和稳定标识。

## 其它读取与资源

- 详情读取冻结路径；月账目、搜索、流水及退款／报销继续读取原分类名字和图标。
- CSV／Excel 使用的月账目数据源读取历史视图，CSV 主机测试验证删除前后输出完全相同。
- 完整备份 schema 为 13，接受旧 schema 2～12，旧包在隔离候选数据库升级。资源枚举包含 category_history_nodes 的自定义图标。
- 账本删除也清理其历史快照，图片清理队列会检查其它账本的历史资源引用，避免误删共享图标。

## 验证边界

主机测试使用临时／内存 SQLite；资源枚举和备份合法性使用生产方法，但没有执行设备文件选择、完整原生 ZIP 备份恢复或原生数据库升级。没有运行 ArkTS 构建、模拟器、真机或删除设备数据。实际设备的迁移、渲染、长按排序与删除确认仍需验收。

删除提示修正：原生 RDB 异常可能不包含触发器 RAISE 文本。仓储现在在 DELETE 前显式查询子分类、预算、预付款及最后一个可用分类，并抛出稳定的应用错误；数据库触发器继续独立校验。预付款提示明确为“该分类仍被预付款项目或核销记录引用，暂不能删除”。错误区的刷新按钮使用品牌色胶囊与白字，不使用系统默认蓝色。

### 删除阻挡项的查看入口

预付款引用阻止删除时，分类页读取当前账本内实际关联的项目，显示项目名称及关联事件数量，并提供“前往查看”打开已有预付款详情。查询与删除守卫采用相同口径：付款预设 JSON 分类或关联交易分类任一匹配即计入，包括草稿、已撤销记录；同一事件不会重复计数，按项目分组。此入口只查询和导航，不自动修改预付款、分类或历史账目。读取失败明确提示，可重新尝试删除以重新查询。

从此入口打开详情后，系统返回和标题返回均回到分类管理；若正在编辑则先关闭编辑。分类页保持挂载，保留原来的收支类型、子分类位置及滚动位置。从普通预付款入口进入的详情仍先返回项目列表。处理后可回分类页再次尝试删除，以实时校验引用；页面展示的引用清单不作为删除授权依据。

验证：`node tools/verify-category-deletion.mjs` 覆盖真实临时 SQLite 关联查询、JSON／交易两种命中及去重、清单读取失败、忙碌状态退出、详情返回调用方及普通详情返回列表。原生编译和设备导航尚需真机验证。
