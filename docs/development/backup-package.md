# 完整备份包 v1

本地保存、恢复和 WebDAV 统一使用 `.xqbackup`。它是标准 ZIP STORE 容器，包含数据库、账单图片和自定义图标。当前备份文件本身未加密。账目图片上传、详情预览和编辑关联已接入；自定义分类、账户图片图标的业务选择仍待后续接入。

```text
manifest.json
ledger.db
assets/images/<sha256>.png|jpg|webp
assets/icons/<sha256>.png|jpg|webp|svg
```

清单包含 `format=xiaoqiao`、`version=1`、`schema=4`、UTC 创建时间和每个数据库/资源文件的相对路径、字节数、SHA-256、CRC32。清单不包含自身。格式版本和数据库版本独立保存；读取 `schema=2/3` 的旧包时会在候选数据库副本上依次升级到 V4，无法识别的版本仍明确拒绝，不猜测导入。标准 ZIP 工具可以读取此容器；应用只接受本版本生成的 STORE 条目，不接受重新打包后的压缩、ZIP64、多磁盘或加密 ZIP。

## 资源契约

资源根目录按数据库隔离在 `filesDir/ledger_assets/<数据库名不含扩展名>/`。`workspace.backup.resources.put('images'|'icons', URI)` 检查支持的文件格式，生成哈希文件名，返回相对路径、哈希、大小和 MIME。相同内容、相同类别去重，已有文件需重新核对哈希。SVG 限静态图标，拒绝脚本、外部引用、事件处理属性、DTD、实体和 CSS URL。

现有 attachments 表的 relative_path 保存 `images/<hash>.<ext>` 等相对路径，content_sha256 和 byte_size 与文件一致。自定义分类、账户图标使用 `icon_key=resource:icons/<hash>.<ext>`。应用自带资源继续使用已有图标 key，不重复打包。当前没有自动资源垃圾回收；资源文件不可变，业务不应原地修改或删除仍被引用的文件。

包内纳入资源目录中的全部合法文件，核对数据库中全部附件和自定义图标引用。附件状态必须 ready。缺文件、哈希不一致、大小不一致或不安全路径均拒绝备份。无需新增表或数据库迁移。

## 有界读写与输入检查

当前完整包最大 32 MiB，最多 2048 个条目（含清单和数据库）。ZIP 写入按 64 KiB 分段落盘，文件同步后才复制到用户目标或上传。预览使用有上限的缓冲，未声明无限容量或流式下载能力；后续调整传输上限不需要改变此资源和清单格式。

解包前检查中央目录与每个本地头一致，拒绝路径穿越、绝对路径、反斜线、额外条目、重复路径、符号链接、加密、压缩炸弹、数据描述符及重叠文件区域。只写入白名单文件名。随后核对 CRC32、清单 SHA-256、资源格式、数据库结构、完整性、外键和资源引用。所有检查均在暂存区执行，预览不改变现有账本及资源。

## 数据库与资源共同回退

数据库快照仍由 LocalLedgerBackup 在 RdbSession 串行队列内生成、校验和恢复。LedgerBackupPackage 负责资源与完整包。恢复回调也在同一数据库队列内执行，业务写入不会穿插在资源切换和数据库恢复之间。

1. 保留原数据库的持久回退快照，再复制到本次完整回退目录。
2. 核对原资源及数据库引用，持久保存 journal，记录原数据库哈希、原资源清单及原目录是否存在。
3. 将原资源目录重命名到回退目录，再将经过检查的暂存资源重命名为当前资源。资源暂存、当前目录和回退目录均位于 filesDir 下，避免跨数据库挂载点重命名。
4. 恢复数据库并检查，通过后原数据库回退文件完成既有登记。
5. 通过原子重命名，将本次完整回退目录登记为最近的恢复前副本。这一步同时移除活动 journal，是数据库与资源共同提交的标记。

恢复失败时先回退数据库，再检查并恢复原资源。应用启动在读取任何业务数据前处理未完成 journal，重新核对回退数据库及资源哈希，恢复原快照。恢复可重复执行；哈希损坏或回退失败时保留记录，阻止继续使用该连接。断电、介质损坏和文件系统持久化时序仍需真实设备专项验证，模拟中断不能代替断电测试。

最近的恢复前副本包含原数据库和原资源，可重新导出为同格式完整包。旧的内部纯数据库回退仍存在，但不作为用户完整备份入口。用户页面只接受 `.xqbackup`，没有新增旧 `.db` 导入兼容分支。

## 收支转账颜色设置

收支转账颜色保存在现有数据库 `db_meta.transaction_colors_v1`，完整数据库快照天然包含此设置，不额外增加偏好文件或更改包格式。恢复前显式验证色板与红／绿互斥规则（黑色可共用）；旧备份缺少该键时使用默认色。恢复成功后重新读取并发布到 UI，数据库恢复失败时继续沿用原设置。细节见[收支转账颜色](transaction-colors.md)。
