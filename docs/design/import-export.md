# 导入导出：页面与交互规则

日期：2026-11-01。用户确认同时覆盖通用 Excel/CSV 和支付宝、微信账单模板。本轮为 Figma 设计，不实现文件解析、数据库写入或服务接入。

## 范围

- 导入：Excel（.xlsx）、CSV；支付宝、微信支付的字段识别模板；通用字段映射及可复用映射配置。
- 导出：Excel、CSV；选择账本、时间、账户、收支类型和字段。附带图片原件时生成表格与图片的 ZIP 包。
- 表格导入与完整备份恢复是不同入口。此次不承诺通过 CSV/Excel 或导出 ZIP 恢复图片原件；完整恢复仍使用备份恢复流程。
- 模板按实际文件表头与样例提供建议，不按服务名称跳过验证，不假定固定列顺序或所有历史版本具有相同列名。
- 所有画板文件名、商户、记录和数量均为虚构演示，不上传真实账单到 Figma。

## 主要流程

选择来源/文件 → 文件内容设置 → 字段映射 → 账户分类匹配 → 数据预览与问题检查 → 明确确认 → 导入结果。

Excel 显示工作表和表头行；CSV 显示表头行、编码和分隔符。无法读取的文件停留在检查阶段，不写入账目。

手机字段映射采用纵向白色映射项，每项包含小巧字段、文件列选择和源列样例；平板采用字段/文件列/样例对照表。字段点击后打开源列选择 Sheet，显示列号、列名与样例；存在同名列时也能区分。未使用的源文件列不自动导入。

## 字段与值的两层匹配

第一层决定文件列与小巧字段的关系。日期、类型、金额、币种都必须有效。日期与金额需能从文件正确解析，不能把缺失金额补成0；类型和币种允许用户明确设置统一值。可选映射包括账户、分类、标签、备注、商户、地址、来源记录编号、优惠、实际扣款、汇率、报销与计入规则。

第二层决定名称和值的含义。例如“零钱”和“微信支付”可由用户明确匹配到“微信零钱”；分类保留层级路径，不只按末级同名分类自动匹配。分类可以来自完整路径列，或按顺序组合多个层级列；父分类仍可直接使用。未匹配账户/分类需选择已有项、明确新建、明确不使用适用的可选字段，或将对应记录留待处理；不能默默创建重复项或归入“其它”。

导入目标账本在预览中明确选择。字段不使用、文件列为空和采用默认值要区分；同一文件列不能因误操作同时承担互相冲突的金额含义。

## 导入与当前账户余额

用户已确认：每次新导入默认保持当前账户余额，预览中允许手动切换为按记录更新余额。默认方式仅补历史账目；收支统计和预算仍按记录日期及计入规则处理。这个批次选择不等同于“计入资产”字段，不应通过改写原始资产标记来替代。

切换到更新余额时，预览按账户、按账户币种列出变动，不把不同币种直接相加。原币转账作用于两侧账户，本金不计普通收支。示例112条有效记录由110条支出、1条收入、1条转账组成：支出2,486.00 CNY、收入8,600.00 CNY、账户间转账100.00 CNY；对应微信零钱变动−2,586.00 CNY，日常储蓄卡变动+8,700.00 CNY，合计净变动6,114.00 CNY。这是虚构的设计汇总，不是现有数据库计算结果。

“更新余额”只作用于用户明确选择的本批次，不作为字段映射模板的隐含默认。更换文件应回到保持当前余额的默认值，重新检查。后续编辑或删除导入记录也应尊重首次导入时的余额处理方式，避免补录记录在后续操作中意外改变余额；具体数据方案留待开发阶段确认，本轮不修改数据库。

## 金额、币种与交易类型

- 金额列表示实付时，不再减一次优惠。表示优惠前金额时，需同时指定优惠列并检查实付结果。演示：30.00 − 2.00 = 28.00。
- 货币符号不是币种唯一标识。符号与已指定币种矛盾时需要处理，不能只去掉符号后套用缺省币种。缺省币种必须由用户确认；不因数字显示两位小数就假定为人民币。
- 原币、账户实际扣款、本位币折算、本笔汇率与汇率来源分开处理。缺少必要换算信息时标记待处理，不用当前汇率补造历史结算值。
- 金额和币种精度遵循币种规则；设计示例校验使用十进制定点含义，不代表应用金额实现已完成。
- 支出、收入、转账的来源值需明确匹配。符号与类型矛盾、未知类型或状态需要检查；不能仅凭正负号把退款当作普通收入。
- 账户间转账必须补齐两侧账户与相应金额/币种。本金不计普通收支与预算，手续费按已有支出规则另行处理。
- 退款、撤销、未完成及状态不明的记录先标记，不自动导入为普通收支，也不在本轮新增退款业务模型。特殊记录代表页展示用户补齐两侧账户后明确按转账处理。
- 来源交易编号按文本保留，不能转为浮点数或丢失前导零；Excel 导出也需保留文本语义。

## 预览、重复与失败

演示数量固定为：120条文件记录 = 112条有效记录 + 5条疑似重复 + 3条需处理记录。预览代表态选择112条，并明确确认跳过8条；修改选择后，数量和按钮文案应同步变化。画板勾选态代表用户已经确认；真实首次预览不能自动勾选“确认跳过”，未确认时主操作应禁用。没有未选记录时省略这项确认。

疑似重复是核对提示，不自动删除、合并或覆盖现有记录。来源编号可参与判断，日期/金额/账户相近不能单独证明重复。用户可选择保留导入或跳过。

问题记录显示源行号、原始值、原因和处理入口。导出问题清单仅在本机保存，不自动发送。确认前不写入；进度页的“处理56/112条”不是已提交56条的承诺。

失败代表态展示“本次导入已撤回”。这是后续实现需要满足的行为要求，不代表当前已经实现事务或回滚。若未来不能确认回退成功，不能展示“原有记录保持不变”或直接重试成功状态，应另行设计检查与恢复流程。

## 导出

原币金额与币种共同保留；涉及换算时分别保留实际扣款、本位币金额和汇率。账户、分类标签、商户地址、备注、图片元信息、报销状态、计入预算和计入资产可选择。

Excel/CSV 代表态都使用2026年10月、128条导出记录，区别于9月的导入示例；切换导出格式不重置范围。文本字段不按公式执行，来源编号不丢失前导零。

Excel/CSV 的字段含义一致，系统保存/分享与文件生成是不同状态。未选择保存位置前，只能显示“已生成”，不能显示“已保存”。附带原图则生成包含表格和原图的 ZIP，未附带时仅导出图片数量与附件标识。

不导出 WebDAV 密码、令牌等凭据。表格导出不替代完整备份。

## 视觉与开发标注

沿用现有浅灰 F1F3F5 页面、纯白无描边卡片、橙红渐变主操作。手机边距16vp，平板32vp；常用卡片圆角16vp，操作20vp，Sheet24vp；模块间距12/16vp。文字开发使用fp，布局使用vp；系统默认字体，数字DIN系列，Figma字体仅作预览。

使用可编辑的原生 Auto Layout，字段文字列 Fill、图标固定、内容高度 Hug。滚动视口和底部操作分离，避免长映射列表遮挡确认按钮。重复行尚未全部组件化或绑定 Variables，不把布局重建等同于完整组件系统。
